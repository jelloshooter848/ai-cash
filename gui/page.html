Burn policy — what every payment costs

These start at a demo value, not at zero. Rate 10,000 ppm is 1% of each exchange, capped at 1,000 mc, with amounts of 10 mc and under exempt. It is deliberately small, and it is here so that a first run burns something real and the cost line in section 3 has something to show. For a mint where a payment moves its whole amount, set both rate and cap to 0.
To change any of this on a running mint: press Stop mint, edit these fields, then press Start mint again. They are locked while it runs because the mint reads them once, at startup.
The burn is min(cap, sum × rate ÷ 1,000,000), where sum is the face value of the coins the exchange spends — not the amount asked for. §7.3 charges it on the inputs, and a wallet almost never holds exact change: paying 7,000 mc out of coins worth 7,100 mc burns 71 mc, not 70. The exact figure for a payment comes back from the mint in the cost line before you pay; the formula here is what it is computed from. A cap of 0 means no burn at all, whatever the rate says — leave both at 0 for a mint where a payment moves the whole amount. For a 1% burn capped at 1,000 mc, set rate 10000 and cap 1000. An exchange whose inputs come to the exempt figure or less never burns. A payment is burned twice: once when the paying wallet splits its coins, and again when the recipient redeems the tokens — both are shown in the cost line before you pay. The mint id and baseline are written into the mint's identity file the first time it runs and cannot be changed afterwards; the burn policy can.

Operator funding — create money and put it in a wallet

There is one current wallet on this page. This dropdown and the active wallet in sections 2 and 3 are the same thing — change either and both follow.
Issuing creates new money out of nothing. It is signed into the supply snapshot and cannot be undone. Crediting it to the wallet is an exchange like any other, so the mint burns part of it on the way in — the line above says how much, before you press.

2Wallets

Click a wallet to make it the active one — that is the wallet that gets funded in section 1 and that pays and receives in section 3. Creating a wallet makes the new one active straight away, so after creating alice then bob it is bob that is active; click alice to switch back. Each wallet is one sqlite file in the workdir; whoever has the file has the money. A row's figure is what that wallet can spend. Value it has already handed out as bearer strings that nobody has redeemed is shown beside it in its own colour: that money is not in the balance and cannot be spent from here, and it is still money somebody can take.
